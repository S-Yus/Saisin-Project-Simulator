# 市場データ・商品条件・イベントの入力仕様と取込手順

実データ・利用許諾・取引条件は捏造しないこと。分からない項目は空のまま検証にかけると、何が足りないかが一覧で表示されます。

## 実データの取込ファイルの作り方
実データは `market-data/` で管理する（出典の一覧と検証結果は [DATA_SOURCES.md](DATA_SOURCES.md)）。
| 場所 | 内容 |
|---|---|
| `market-data/raw/` | 公式サイトから取得した元ファイル。**変更しない** |
| `market-data/catalog.json` | 台帳: 取得元URL・取得日時・SHA-256・商品名・分類・NISA区分・さいしん取扱・取引条件（仮設定）・採用／未採用と理由・ニュース候補・許諾状態 |
| `scripts/build-dataset.js` | 台帳と元ファイルを照合・検証し、`market-data/build/dataset.json`（取込ファイル）と `report.json`（検証記録）を生成 |

```bash
npm run check-data   # 検証のみ（書き出さない）
npm run build-data   # 検証して取込ファイルを生成。エラーがあれば生成しない
```
検証内容: 元ファイルのハッシュ、見出しと全行の形式、日付の重複・逆転、基準価額が正の整数であること、対象期間の行、独立した営業日カレンダーとの差（欠損・余分）、期間不足、分配金（0円以外で支払日データがなければ採用不可）、アプリの取込検証。欠損の補完・丸め・価格の生成は行わない。許諾状態は台帳の値をそのまま出力する（スクリプトは確認済みにしない）。

## 取込手順（管理画面「市場データの取込」・運用担当トークン）
1. JSON ファイルを選ぶ（または貼り付け）。雛形: `examples/dataset.template.json`、価格のCSV雛形: `examples/prices.template.csv`
2. **① 検証（保存しない）** — エラー・警告・件数・対象期間・価格の範囲・商品ごとの行数・条件の確定状況・チェックサムを表示。DB には何も書かない
3. エラー0件なら **② 取込（下書き）**。全件を1トランザクションで保存し、途中で失敗すれば何も残らない。取込ファイルのチェックサム・データ版・件数を記録
4. 出典ごとに利用許諾を確認し「確認済みにする」（確認内容のメモ必須）。下書きの間だけ変更可
5. **データを固定** — **本番**では「全出典の許諾確認済み・全商品条件が確定・基準証券会社が確定」でないと固定できない。**確認用環境**では未確定のままでも固定でき（さいしんの動作確認のため）、残っている未確定事項が結果と参加者画面に表示される。固定時に内容ハッシュを記録し、以後は変更不可（差し替えは新規取込→新しい開催回またはデータ差替え→**動作確認は自動解除**）

環境ごとの規則: 本番・確認用環境は `kind: "production"` のみ取込可。開発・検算環境（`dev`。ループバックでのみ起動）は架空データ（`dev_test`）に加え、実データ形式も**検算用**に取込・固定できる（許諾状態は変わらず、画面に「実データ・利用許諾は未確認」と表示される。`node scripts/dev-seed.js real`）。開発環境のDBは本番・確認用環境に持ち込めない。

## 全体
| 項目 | 必須 | 説明 |
|---|---|---|
| meta.name | ○ | データ名 |
| meta.kind | ○ | `production`（実データ）/ `dev_test`（開発用の架空データ） |
| meta.version | 本番○ | データ版（例「2026-11-01取得版」） |
| meta.period_start / period_end | ○ | 対象期間。確定済み月末までの36か月が基本（外れると警告）。価格データが期間の始め/終わりの7日以内をカバーしないと**必要期間不足**エラー |
| broker_basis.name / status | 本番○ | 基準とする証券会社・販売会社と確定状況（`confirmed`/`unconfirmed`） |

## 商品 instruments[]
共通: `id`（英数字._-、32文字以内）, `type`（stock/etf/fund）, `name`, `category`, `description`（短く）, `source_id`, `terms`。
`terms.terms_status` は `confirmed`（基準証券会社の条件と照合済み）/ `provisional`。**本番データでは下記の必須項目を省略できず、既定値は使われない**（開発データでは既定値で補い「仮設定」扱い）。

株式・ETF の terms
| 項目 | 説明 |
|---|---|
| lot_size | 売買単位（株・口） |
| settlement_days | 約定日から受渡日までの営業日数（買い・売り共通） |
| fee {rate_ppm, fixed, min, max} | 手数料（税込）。rate_ppm は100万分率（0.1%＝1000）。max は null 可 |
| price_limit_table + price_limit_multiplier | 成行買いの確保に使う「基準値段の上限(未満)→制限値幅」の表（円、小数第3位まで）と倍率。取引所・証券会社の規則を転記する |
| buy_reserve_margin_bp | 値幅表の代わりに使う確保率（1万分率）。根拠のある値が決まった場合のみ |

投資信託の terms: `min_amount`, `amount_step`（円）, `nav_offset`（注文日から何営業日後の基準価額か, 1以上。**「申込受付日の基準価額」の商品は1、「翌営業日の基準価額」の商品は2**。理由は SPEC.md §5）, `buy_settlement_days`（購入代金の受渡までの営業日）, `settlement_days`（売却代金の受渡）, `holdback_ppm`（信託財産留保額）, `savings_ok`（積立可否）, `distribution_mode`（`cash` のみ）, `fee`（購入時手数料、金額に含む方式）。任意: `savings_min_amount`, `savings_amount_step`（積立専用の最低金額・単位。未指定なら購入と同じ）, `spot_buy_ok`（一括購入の可否。既定 true。false にすると積立でのみ購入可）。

採用の目安: 6〜10商品。海外資産は国内の円建て商品（ETF・投信）で扱う。データが不足する商品は登録しない。

## 価格 prices[] / prices_csv
JSON 配列と CSV（文字列 `prices_csv`、1行目は `instrument_id,date,open,close,status`、引用符不可）を併用できる。
| 項目 | 説明 |
|---|---|
| instrument_id | instruments の id と一致（不一致はエラー） |
| date | 実在する日付 |
| open | 株式・ETFの始値。投信は指定しない |
| close | 終値／基準価額（1万口あたり）。`halt` の日は空欄可 |
| status | `normal` / `halt`（売買停止・始値なし・基準価額なし）/ `limit`（値幅制限等で成立しない日） |
検出するエラー: 重複（同じ商品・日付）、不正な日付、0・負値・指数表記・小数第4位以降、商品ID不整合、期間外の日付、営業日の欠損（ある日に他商品の行があるのにこの商品の行がない）、価格データのない商品、必要期間不足。CSV のエラーは行番号付き。

## 権利処理 actions[]
| type | 項目 |
|---|---|
| dividend | `ex_date`（権利落日。投信は決算日）, `record_date`（権利確定日。本番必須。投信は決算日＝ex_date）, `per_unit`（1株/1万口あたり・税引前）, `pay_date`（支払日） |
| split | `ex_date`（効力発生日）, `num`, `den`（2:1分割=2,1、1:10併合=1,10）。num が den で割り切れない場合は `fraction_price`（端数処分代金・新株1株あたり）と `fraction_pay_date` が必須 |
検査: 日付が営業日にあること、権利落日 ≤ 権利確定日 ≤ 支払日、株式で権利落日が権利確定日の前営業日でなければ警告、同一銘柄・同日の複数処理は不可。

## ニュース・イベント news[]
任意で `explain`（やさしい解説。300字以内）と `views`（考え方の例。`{label, text}` をちょうど2つ、異なる立場を1つずつ。label 30字・text 200字以内）を付けられる。「買い時」「上がりそう」「おすすめ」「期待リターン」「必ず」「買うべき」など、値動きの見通しや売買のすすめにあたる表現があると取込エラーになる。

`id`, `published_date`（公表日。対象期間内）, `summary`（自分で書いた短い要約。記事の転載・AIによる未確認の補完はしない。200字超は警告）, `source_name`, `url`（http/https）。5〜8件が目安。値動きとの因果関係を断定する書き方はしない。公表日の終了時点まで参加者には表示されない。
