# 要件定義（アプリ 0.7.0 / 計算仕様 1.4）

## 1. 目的
埼玉縣信用金庫（以下「さいしん」）が行う大学生向けNISA・資産形成説明会で、参加者がスマートフォンから使う投資シミュレーター。出典を確認した**過去の実データ**の上で、投資対象の選択・購入・売却・積立・資金配分を自由に試し、価格変動、資産配分、積立、手元資金、判断の結果を体験する。

物語・診断・ゲーム的演出、利益のランキング、特定商品の推奨、投資判断の正解の提示は行わない。

## 2. 利用者
| 利用者 | できること |
|---|---|
| 参加者（匿名） | QRから参加、はじめの質問に答えて自分の資金条件（最初の金額・毎月の金額）を決める、自分の仮想口座の閲覧・注文・積立・時間進行・やり直し（条件の変更も可）・比較 |
| 運用担当（管理者） | 開催回の作成・設定、データの取込・固定、公開・一時停止・緊急停止、保持時間の変更、即時削除 |
| 確認担当（さいしん） | 開催回ごとの動作確認の記録のみ（運用担当とは別のトークン） |

管理者は参加者の口座を閲覧・操作できない（人数などの件数のみ）。

## 3. 優先順位
1 計算の正確さとデータの整合性 → 2 安全性と安定動作 → 3 初心者が迷わないUX → 4 実際の取引ルールの再現 → 5 選択肢の幅と見た目。

## 4. 確定事項
| 区分 | 内容 |
|---|---|
| 価格 | 出典を確認した過去の実データのみ。仮定利回り・乱数・AI・補間・外挿による価格は使わない。データの最終日で進行を終了し、その先の価格・資産額は生成しない |
| 表示 | 対象期間と「過去の実データに基づく取引体験」であることを明示。将来の値動き・購入の有利さを示唆する表示、推奨・順位付けをしない |
| 時間 | 参加者ごとに独立したシミュレーション日付。翌営業日／翌月／月単位の自動進行（停止・再開）。早送りも1営業日ずつ処理 |
| 取引 | 投資信託: 金額指定購入・売却・対象別の積立（変更・休止・再開・解除）。株式・ETF: 成行のみ・翌営業日の寄付き（機能は維持。本番採用はデータ・条件がそろう場合のみ） |
| 資金 | 受渡前の購入証券は売却不可、未受渡の売却代金は再投資不可、注文中の資金・数量を確保 |
| 計算 | 整数演算、税引前、基準価額に含まれる信託報酬を再控除しない、調整済み価格を使わない |
| NISA | NISA対象商品を扱う。**NISA口座と普通の口座（課税口座）の比較**として、利益にかかる税額の概算（20.315%）と手元に残る利益の差を表示する（SPEC §6b）。年間投資枠は、超えた年があればその旨を表示するだけで、買付は止めない。枠の復活・つみたて投資枠と成長投資枠の区分・実際の税務処理は再現しない |
| ニュース | 出典つきの事実の要約に加えて、やさしい解説と「考え方の例」（立場の異なる2つ）を付けられる。値動きの見通し・売買のすすめは書かない（取込時に禁止表現を検査）。どちらの立場もすすめない |
| 説明会限定 | 開催回ごとの開始・終了、終了後は全操作を拒否、開催ごとのさいしんの動作確認が公開の条件、必須3文言を開始・結果・利用中に掲載 |
| データ保存 | 匿名ID。既定は説明会終了の24時間後に削除（変更可）。はじめの質問（学年・収入・支出）への回答は端末の中だけで使い、サーバーへ送らない。サーバーが保存するのは選ばれた2つの金額だけ |
| 画面 | 明るい配色。開始時は1画面1問の質問、参加直後に4ステップの使い方、ホームは「総資産」と「次にやること」を中心に構成し、詳細は折りたたみに置く |
| 構成 | Node.js 24.11.1 ＋ 単一プロセス ＋ SQLite、HTTPSリバースプロキシ配下 |

## 5. 未確定事項（人の判断が必要。値は変更可能な設定）
記入欄は [DECISIONS.md](DECISIONS.md)、現状と影響は [LIMITATIONS.md](LIMITATIONS.md)。
- データの利用許諾（3社。未確認）、採用商品の最終承認、表示するニュースの承認
- さいしんの販売条件（購入単位・手数料・受渡日数・申込不可日・一括購入の可否）
- 初期資金・毎月の追加資金、開催日時・体験時間・最大人数
- 本番設置先、削除保証の運用上の合意、さいしんによる最終動作確認

## 6. 対象外
指値・日中売買・信用取引・空売り・レバレッジ商品・外国市場への直接注文、取引所の板・待ち順位・流動性・市場への影響、税金の計算、分配金の再投資、個人情報の収集、アクセス解析・外部トラッキング、利益ランキング、ニュースからの値動き予測。

## 7. 受入条件
| # | 条件 | 確認方法 |
|---|---|---|
| A1 | 実データの形式・単位・期間・重複・欠損が元ファイルから再検証できる | `npm run check-data`、`test/realdata.test.js` |
| A2 | 購入→受渡、売却→受渡、未受渡資産の制限、手数料・配当・分割が手計算と一致 | `test/engine.test.js`、`test/realdata.test.js` |
| A3 | 全営業日で総資産の恒等式が成り立ち、現金・買付可能額が負にならない | `test/system.test.js` |
| A4 | 1日ずつと早送りの結果が完全一致 | 同上（架空データ・実データの両方） |
| A5 | **データの最終日より先に進めない。架空の価格が生成されない**（成立価格・表示価格がすべて元CSVの値） | `test/realdata.test.js` |
| A6 | 参加者のシミュレーション日付より先の価格・ニュースをサーバーが返さない | `test/system.test.js` |
| A7 | 二重注文・二重進行・複数タブ・通信結果不明時の復旧 | 同上 |
| A8 | 他参加者の情報へのアクセス拒否、管理と参加者の分離 | 同上 |
| A9 | 終了時刻をまたぐ操作の拒否、一時停止・緊急停止 | 同上＋画面確認 |
| A10 | 確認後の重要変更（コード・データ・設定・仮設定）で確認が解除され公開できない | 同上 |
| A11 | 許諾未確認・条件仮設定・確認未完了のままでは本番公開できない。確認用環境は確認の前に動かせ、未確定事項が画面に表示される | 同上、`test/realdata.test.js` |
| A12 | 自動削除・失敗・再試行・アプリ停止中の削除 | `test/system.test.js` |
| A13 | 必須3文言が改変されず、開始・結果・利用中に表示される | 同上＋画面確認 |
| A14 | 画面に推奨・予測・順位の表示がなく、対象期間と「過去の実データに基づく取引体験」が明示される | `test/realdata.test.js`＋画面確認 |
| A15 | スマートフォン幅で主要操作ができ、横スクロールが出ない | 画面確認（[TEST_REPORT.md](TEST_REPORT.md)） |
| A16 | ファイルDB・別プロセスで300人の負荷に耐える | `scripts/loadtest.js` |

## 8. 完成の段階

|---|---|---|

| 本番開催可能な状態 | さいしんの動作確認の記録、開催回の設定確定、本番設置 | **未達** |
