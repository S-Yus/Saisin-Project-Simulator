# 動作確認チェックリスト（開催回ごと・埼玉縣信用金庫の確認用）

## A. 内容
- [ ] 採用商品（名称・分類・説明）、出典・取得日・利用許諾の確認内容が正しい（無料で閲覧できることを許諾と扱っていない）
- [ ] 商品条件（売買単位・手数料・受渡日数・投信の基準価額適用日・購入代金の受渡日・信託財産留保額・成行買いの確保ルール）が基準証券会社・販売会社の条件と一致し、「仮設定」が残っていない
- [ ] 初期資金・毎月の追加資金・期間・開催日時・最大人数・保持時間が意図どおりで、開催回の「仮設定」がすべて外れている
- [ ] 配当（権利落日・権利確定日・支払日・金額）、分割（効力発生日・比率・端数処分代金）が公表資料と一致
- [ ] ニュースが事実で、公表日が正しく、出典と自作の短い要約のみ（因果を断定しない）
- [ ] 開始画面・ホームに対象期間と「過去の実データに基づく取引体験」の表示があり、推奨・予測・順位にあたる表示がない
- [ ] データの最終日に到達すると進行できなくなり、その先の価格・資産額が表示されない
- [ ] 取込データの検証記録（`market-data/build/report.json`）と出典台帳（docs/DATA_SOURCES.md）の内容が一致し、元ファイルのハッシュが台帳と同じ
- [ ] 開始画面・結果画面・利用中（ご利用上の注意）に必須3文言が一字一句同じ。過去実績・再現していない要素・初版の制限（受渡前の売却不可等）・税引前の注記がある

## B. 計算の突合（電卓または表計算で手計算し、画面と比較）
- [ ] 株式の買い: 確保額 → 翌営業日始値で約定 → 手数料 → 受渡日に現金残高が減る／それまで買付可能額だけが減る
- [ ] 受渡前の株式・口数は売却できず、理由が表示される。受渡後は売却できる
- [ ] 売り: 一部・全売却、受渡日までの未受渡代金は買付可能額に含まれない、受渡前後で総資産が変わらない
- [ ] 投信の金額購入（手数料込み→口数・端数）、売却（留保額・受渡）、積立（発注日・金額変更・休止・再開・解除）。例: ハッピークローバー1年を開始日（2023-11-01）に10万円購入 → 2023-11-06 の基準価額 14,310円で 68,377口、手数料 2,152円（docs/TEST_REPORT.md §2）
- [ ] 配当: 権利付最終日までに約定した保有に対して確定し、支払日に入金。分割: 数量・端数処分代金
- [ ] 値上がりで確保額を超えた買いが失効、売買停止日の注文が失効、価格更新なしの日の評価
- [ ] 1日ずつ進めた結果と「翌月へ」「自動進行」の結果が同じ（同じ操作で最終総資産を比較）

## C. 操作・運用（スマートフォン縦画面で）
- [ ] 参加 → 初回案内 → 商品選択 → 注文（入力→確認→受付）→ 積立 → 早送り → 売却 → 結果確認 → やり直し → 比較
- [ ] 注文の取消（当日のみ）、買付可能額・保有の超過は理由付きで拒否、入力が消えない
- [ ] 機内モード等で通信を切って注文 →「受付状況を確認」で、受付済みなら結果、未受付なら同じ内容で再送でき、二重にならない
- [ ] 自動進行の停止理由と次の操作の表示。自動進行中は注文できない
- [ ] 2つのタブで同時に進行・注文しても二重にならない
- [ ] 一時停止・再開・緊急停止、終了時刻の拒否、開いたままの画面の終了表示、端末の時計変更で延長できない
- [ ] 他の参加者の口座が見えない（別端末）
- [ ] テスト用の開催回で保持時間を短くし、削除・削除記録・失敗時の警告を確認
- [ ] QRから参加、定員超過で拒否。想定人数での負荷確認（確認用環境で `scripts/loadtest.js` 相当、または実機での同時操作）

## D. 記録と公開
- [ ] 確認用環境で確認担当トークンを使い、確認者名・確認記録番号を記録した
- [ ] 本番の開催回の構成指紋が確認用環境と一致することを確認し、本番にも確認を記録した
- [ ] 確認後にコード・データ・設定・仮設定を変更していない（変更した場合は自動で確認が外れ、公開できない）
